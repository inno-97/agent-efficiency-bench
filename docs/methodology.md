# 실행·평가 방법

1. 과제·버전과 실행 구성(에이전트·모델·버전·추론 설정·협업 역할)을 선택합니다.
2. 동일한 시작 커밋, 고정 의존성, 새 작업 폴더와 새 세션을 사용합니다.
3. 공통 prompt로 실행하고 시간·원본 사용량·사람 개입을 기록합니다.
4. 최초 제출 커밋과 결과를 보존합니다.
5. 에이전트가 수정할 수 없는 별도 사본의 공통 평가 테스트로 검증합니다.
6. 동일한 형식의 실패 결과를 제공해 최대 2회 수정합니다. 최초/수정 라운드별 커밋과 측정값을 보존합니다.
7. 최종 테스트 결과와 미해결 결함을 제출합니다.

## 공정성

- 시간 예산, 권한, 네트워크, OS, 도구, 테스트 공개 범위를 과제별로 사전 고정합니다.
- 사람이 직접 코드를 수정하지 않습니다. 추가 지시·승인·질문 답변은 개입으로 기록합니다.
- 실행 사이 코드·설계·리뷰 결과를 전달하지 않습니다. 공통 정책 답변은 모든 실행에 동일 적용합니다.
- 테스트 공개 여부와 에이전트의 평가 테스트 접근 여부를 기록하고 다른 조건의 결과는 분리합니다.
- build는 전체 인수 기준 충족, fix는 결함 테스트와 기존 기능 회귀 테스트 모두 통과해야 완료입니다.
- 평가 테스트 삭제·완화로 얻은 통과는 인정하지 않습니다.
- 중단·시간 초과·실패한 실행도 기록합니다. 완료한 실행끼리 자원을 비교합니다.
- 반복 실행 시 모든 결과와 분산을 보고합니다. 1회 실행은 탐색적 결과로 표시합니다.

과제 준비 완료 전에는 성능 결과를 발표하지 않습니다. 초기에는 수동 실행·결과 제출을 지원하고 자동 연동은 후속 작업입니다.
