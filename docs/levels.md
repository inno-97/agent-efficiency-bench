# 프로젝트 규모: L1~L4

레벨은 잠정적인 복잡도 구간이며 코드 줄 수와 예상 모델 응답 시간으로 판정하지 않습니다. 지원하는 각 과제의 명세와 테스트가 비교 단위입니다.

| 레벨 | 규모 | 서버·외부 경계 | 평가 초점 |
|---|---|---|---|
| L1 | 한 화면의 초소형 앱 | 로컬 저장만 | 기본 상태·ID·복원 |
| L2 | 집계 또는 목록·상세·편집을 갖춘 소형 앱 | 로컬 저장만 | 검증·집계·여러 화면의 일관성 |
| L3 | 사용자 데이터 또는 기기 기능을 다루는 소형 완결 앱 | 웹 인증/DB, 모바일 사진 권한·파일/DB | 인증·소유권 또는 기기 경계 |
| L4 | 여러 사용자의 권한 또는 여러 기기의 상태를 다루는 중소형 앱 | 웹 멤버십/권한, 모바일 서버 동기화 | 교차 리소스 권한·오프라인·충돌 |

## L1·L2 확정 범위

- 웹 L1: Todo 한 화면, 목록 변환·localStorage. UI scaffolding 제공.
- 웹 L2: 지출 목록·입력/편집 영역·월/분류 필터·합계. UI scaffolding 제공.
- Android L1: 습관 한 화면·날짜별 체크·SharedPreferences. UI/저장 scaffolding 제공.
- Android L2: 운동 목록·상세·편집 세 화면(패널 전환)·날짜별 운동량·SharedPreferences.

build는 사업 로직 TODO를 완성하는 constrained build입니다. 빈 저장소에서 UI까지 모두 설계하는 greenfield 과제는 아닙니다. fix는 동일 계약의 정상 코드에 특정 결함을 넣은 과제입니다. build/fix 결과를 섞어 비교하지 않습니다.

전체 경과 예산: L1 30분, L2 60분(수정 최대 2회 포함). 환경 설치·캐시 준비는 측정 전 완료. 실제 모델 소요 시간과 토큰은 아직 미측정입니다.

L3·L4의 기준 스택은 [기술 스택 문서](stack.md)로 확정했습니다. 웹은 TypeScript/Next.js/PostgreSQL, Android는 Kotlin/Compose/Room입니다.

## L3 — 스택 확정, 과제 구현 전

**웹: 개인 북마크 보관함**

- 로그인·로그아웃·서버 세션, 본인 북마크 CRUD, 태그·검색·페이지네이션.
- 대략 로그인·목록·상세/편집 3~4개 화면. User/Session/Bookmark/Tag와 연결 관계.
- API 직접 요청의 인증·데이터 소유권·입력 검증, 새로고침/서버 재시작 후 보존을 평가.
- 공개 회원가입·공유·권한 계층·외부 페이지 크롤링은 제외. 계정은 seed.

**모바일: 오프라인 메모**

- 목록·상세·편집·검색, 태그, 로컬 DB, 사진 1장 첨부와 파일 보존.
- 대략 3~4개 화면. 사진 선택 취소·파일 접근 실패, 앱 재실행, 사진 삭제와 데이터 무결성 평가.
- 로그인·클라우드 동기화·OCR·음성·리치 텍스트는 제외.

## L4 — 스택 확정, 과제 구현 전

**웹: 소규모 팀 이슈 보드**

- 로그인·프로젝트 목록/상세·이슈 상세, 기본 멤버 관리. 대략 4~5개 화면.
- User/Session/Project/Member/Issue/Comment 관계, 소유자·멤버·작성자별 서버 권한.
- 다른 프로젝트 ID 접근, 작성자 위조, 멤버 제거 후 접근 차단, 수정 후 회귀 평가.
- 결제·다중 조직·초대 이메일·실시간 채팅·첨부 파일·복잡한 관리자 화면은 제외.

**모바일: 개인 체크리스트 동기화**

- seed 계정 로그인·목록·상세/편집·동기화 상태, 로컬 DB와 작은 로컬 서버.
- 오프라인 CRUD·재연결 재전송·중복 방지·두 클라이언트 충돌을 평가.
- 충돌 규칙(예: 서버 버전과 요청 ID), 삭제 정책과 재시도 규칙은 과제 제작 시 고정.
- 팀 공유·권한 계층·실시간 공동 편집·푸시·실서비스 배포는 제외.

L3/L4는 이 범위에서 별도 명세와 고정 환경·평가를 만든 뒤 ready로 전환합니다. 웹과 모바일 동일 레벨이 동일 토큰/시간을 의미하지 않습니다.
